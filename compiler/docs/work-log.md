Tests compare schema root fields with runtime models, assert the exact capability surface, derive the set digest independently from named member digests, mutate capability/target/input-order sources, run every negative fixture, and exercise every declared diagnostic.

## WS2 - Early tracer bullet - 2026-08-05

**Delivered:** A hand-written, no-AI tracer from canonical Clinical IR through content-addressed capability resolution into a CHT 5.2 form/task bundle; a registered `current_contact` read of the most recent LMP with missing/stale handling; the deterministic `technical.gestational-age.naegele` Python and CHT extension implementations; explicit caller branches for all eight registered statuses; typed `technical.ga_weeks`, `technical.ga_days_remainder`, and `technical.edd` binds; a single-contact report task whose seven-day interval is resolved from an integer decision-table output; content-preserving, idempotent composition into an unrelated `tasks.js` fixture with exact rollback bytes; hand-derived calendar vectors; a locked TypeScript differential oracle; a local Node/XForm structural harness; and a deterministic E2 evidence manifest whose environment section separately records the exact CHT sandbox as `not_run`.

**Deviations:** The TypeScript handoff is retained as a differential oracle through Release 1 rather than ported into or invoked by the production Python runtime. The local harness verifies generated XForm wiring and executes the emitted extension module, but it is not the official form runner or an exact CHT 5.2 sandbox; therefore it earns only E2. The clinical endpoint and interval are explicitly synthetic tracer policy, not ministry- or clinician-approved care guidance.

**Defects found:** Canonical IR had no implementation-independent capability invocation, so a model could not name a registered function without leaking Python or CHT details. Task timing was initially stored directly on the task action rather than produced by the decision table. Calculated technical outputs defaulted to string XForm binds. The reviewed TypeScript composer requires trusted prior-composition state for a second pass. Windows newline translation initially made the recorded composed hash differ from the written artifact. The tracer runner initially located the external TypeScript handoff without re-verifying the source-lock digests, and its first local harness executed the extension without checking the generated form wiring.

**Root cause:** The registry, IR, form, and task contracts had previously been tested mostly within their own layers, so the missing cross-layer references and serialization invariants were invisible. Recomposition and oracle reuse also depended on state/version assumptions that were present in the reviewed TypeScript tests but not represented in the first Python bridge.

**Generalized guardrail:** `invoke_capability` carries only a capability ID, ordered variable arguments, status target, and output mappings; registry resolution supplies implementation bindings. Stable `CHWN-RESOLVE-*` diagnostics and negative tests cover unresolved and malformed invocations. Every registered status must appear in an explicit caller branch. Static task lowering may reference a typed decision output only when every triggering rule resolves to one deterministic non-negative interval; missing or ambiguous policy fails with `CHT-TASK-003`. XForm calculate rows can preserve explicit bind types. The bridge re-verifies every locked TypeScript source digest, rejects errors on either composition pass, writes composed bytes with explicit LF newlines, compares rollback bytes and unrelated source bytes, and keeps comparable versus non-comparable oracle cases separate. Two clean builds must have identical deterministic manifest sections.

**Status ledger:** WS2 focused tracer/composition suite: 13 pass, 0 fail, 0 skipped. Full compiler suite: 178 pass, 0 fail, 1 environment-dependent official-harness skip across 179 tests. The local Node/XForm tracer harness passes. Five tracer vectors are comparable with the TypeScript oracle and pass after normalization; two invalid/out-of-domain vectors are counted separately as not comparable. Task recomposition is byte-identical and rollback exactly matches the input fixture.

**Evidence level earned:** E2 for the tracer. `deployment_ready` is false. Successful bundle generation, non-empty JSON, local Node execution, and TypeScript agreement are not CHT deployment evidence.

**Blocked on:** Exact CHT 5.2 sandbox execution is E4 external evidence and remains `not_run`; the existing official local-data harness is skipped on this Windows environment because `xsltproc` is not executable. Representative-device offline/sync, battery, memory, accessibility, and translation checks remain E5 external work, and clinical/governance/deployment approval remains E6 human work. Before any later offline queued-request or messaging work, topology and registry references must be re-resolved against a current snapshot; WS2 does not decide that staleness policy. Group-scoped obligations remain outside the `current_contact` model and require a separate design or pilot descope. Native WFA remains non-comparable until the deployment-controlled chart document bytes and version are supplied.

## WS3 - Governed registry release - 2026-08-05

**Delivered:** Tracer-informed WS3-WS9 Codex work specifications; a versioned v2 registry set that leaves the executable WS1/WS2 capability contract unchanged; a data dictionary with identifiers, value-set, type/unit/cardinality, requiredness, owner role, retention/consent/access references, interoperability mappings, provenance, and lifecycle; a capability-governance sidecar bound to exact executable capability and data-concept digests; detached clinical, data-governance, and technical attestation contracts; a separately content-addressed release contract; fail-closed activation requiring exact set/release/attestation digests, three distinct roles and people, approved decisions, current lifecycle, current timestamps, and a caller-supplied signature verifier; an unpopulated human approval template; sealed synthetic positive and negative fixtures; and stable `CHWN-REG-007` through `CHWN-REG-015` diagnostics.

**Deviations:** Production signature verification is represented by a required verifier boundary rather than an invented trust store, key, or signing service. All executable approval evidence uses visibly `synthetic-test-*` identities. Real owners, policy references, organizations, keys, signatures, jurisdiction, effective dates, and approval decisions remain unset. Registry-set v1 remains supported for the WS2 tracer but is mechanically non-activatable.

**Defects found:** The first governed shape included a data dictionary without binding capability parameters to its concepts, which would have made the dictionary ornamental. The first activation path trusted callers to have used strict parsers and could therefore accept directly constructed models without recomputing their digests. The first role check did not prohibit one person from filling multiple required roles or future-dated attestations. Adding exact concept bindings immediately found a real synthetic contract mismatch: the data concept used unit `date` while the executable capability used `calendar_date`.

**Root cause:** Previously independent capability, concept, and approval objects shared human-readable names but no mandatory cross-artifact digest/type/unit invariant. Trust was placed at parser entry points instead of re-established at the irreversible activation boundary. Role labels were checked as a set without checking the identity and time semantics of each attestation.

**Generalized guardrail:** A governed capability must bind each declared concept use to an exact concept ID, version, digest, direction, and parameter; the compiler checks that parameter and concept types and units agree. Every executable capability in a v2 set requires governance. Activation reparses and rehashes the registry set, release, and every attestation regardless of object provenance; requires exact attestation-set equality; rejects missing/duplicate roles, duplicate approver identities, rejected/unverified/expired/future-dated attestations, inactive members, superseded releases, and v1 sets; and has no default signature verifier. Schema/runtime field parity, unknown-field rejection, digest mutation, cross-binding mutation, direct-model tampering, and every diagnostic are automated tests.

**Status ledger:** WS3 data-dictionary and governance suite: 14 pass, 0 fail, 0 skipped. Full compiler suite: 192 pass, 0 fail, 1 environment-dependent official-harness skip across 193 tests. Human approval: `not_supplied`. Production signature trust service: `not_supplied`. Exact target/runtime and representative-device evidence: `not_run`.

**Evidence level earned:** E1 for deterministic schemas, digests, negative cases, and synthetic activation tests. The synthetic fixture proves fail-closed mechanics only; it is not an approval record. E6 remains `not_supplied`.

**Blocked on:** `[HUMAN INPUT]` must supply actual policy references, named owners, jurisdiction, effective interval, three independent approvers, organizations, signing-key IDs, and decisions. A production trust configuration must verify detached signatures. Exact CHT runtime, device/offline, accessibility/translation, security/privacy, operations, and deployment evidence remains external. None of these blockers prevents WS4 prompt evaluation or WS5 deterministic bridge development, but no governed production release can activate without them.
